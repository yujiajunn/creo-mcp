# Creo MCP 与 Skill 工程化边界

## 目标

Creo MCP 是一层通用、确定、可验证的 Creo 操作能力。它负责通过 PTC 官方
VB API 与 Creo Parametric 交互，但不绑定针管、吸塑盒或其他具体产品。

推荐的调用关系是：

```text
Agent
  -> 产品或工艺 Skill
    -> 通用 Creo MCP 工具
      -> PTC 官方 VB API / COM
        -> Creo Parametric
```

Skill 是可选的。没有 Skill 时，Agent 也可以直接组合 MCP 工具完成探索性或
一次性的建模；使用 Skill 后，可以把建模过程变成稳定、可重复、可检查的
工程流程。

自动建模后的人工接手、语义命名、模型树组织、修改入口和日志要求见
[`ENGINEERING_STANDARD.zh-CN.md`](ENGINEERING_STANDARD.zh-CN.md)。

## MCP 负责什么

MCP 负责“Creo 能可靠地做什么”，包括：

- 连接并确认当前 Creo 会话。
- 打开 Creo 原生模型，导入外部 CAD 文件。
- 读取模型、装配、特征、基准、尺寸、参数和几何信息。
- 创建和编辑草图、约束以及原生 Creo 特征。
- 执行拉伸、旋转、扫描、壳体、圆角、阵列、镜像等通用操作。
- 重生成模型，并读取操作后的真实结果。
- 处理单位换算、坐标系和引用关系。
- 分离打开、修改、保存和导出权限。
- 返回结构化结果与明确错误，而不是依赖 Creo 弹窗文字。

MCP 不应该出现针管、吸塑盒等业务专用的核心接口。如果一个完全不同的产品
无法自然复用某个工具，该行为通常不应该放在 MCP 中。

## Skill 负责什么

Skill 负责“为了某个产品或工艺，应该如何使用 MCP”，包括：

- 选择哪些 MCP 工具以及调用顺序。
- 针管、活塞、针座等产品由哪些参数描述。
- 吸塑盒的间隙、壁厚、圆角、拔模角和型腔规则。
- 如何从参考产品的包络或曲面生成包装结构。
- 特征命名、模型树组织、参数命名和交付检查清单。
- 每一步完成后应该检查哪些 MCP 返回值。
- 特征失败、引用丢失或重生成失败后的恢复策略。
- 公司、客户或项目特有的审批流程。

Skill 可以比 MCP 更严格，但不能绕过或削弱 MCP 的底层安全规则。

## 不使用 Skill 与使用 Skill 的区别

### 直接使用 MCP

适合：

- 临时建模和探索性设计。
- 单次修改、测量或格式转换。
- Agent 已经拥有完整、明确的建模要求。
- 调试新的 Creo 能力。

直接使用时仍然受到 MCP 的单位、命名、防覆盖和确认机制保护。

### 使用 Skill

适合：

- 重复生产同类产品。
- 需要统一尺寸关系、工艺规则和模型树结构。
- 需要稳定的失败恢复、检查和交付流程。
- 多个 Agent 或人员需要执行同一套工程标准。

Skill 不会凭空增加 Creo 能力。MCP 没有提供的操作，Skill 也无法可靠完成；
因此应先完善通用 MCP，再建立产品 Skill。

## 必须由 MCP 强制的约束

以下规则不能只写在提示词或 Skill 中，必须由代码校验：

- 文件路径必须明确且经过验证。
- 文件格式不能靠有歧义的扩展名盲猜。
- 单位必须读取、报告，并在需要时确定性换算。
- 模型名、特征名和参数名必须符合 Creo 要求。
- 写操作必须明确目标模型和引用对象。
- 修改前必须确认所有必要引用均存在。
- 修改后必须重生成并检查真实结果。
- 打开模型不代表允许修改，修改模型不代表允许保存。
- 导入和新建模型默认保持未保存状态。
- 保存和导出必须是独立、显式确认的操作。
- 默认禁止覆盖、删除、清除或替换现有模型文件。
- 超时、COM 异常和 Creo 原厂错误必须转换成结构化错误。
- 可重试操作需要稳定的计划标识或操作标识，防止重复执行。

## 工具设计规范

每个 MCP 工具只承担一个清晰、可验证的操作，并使用严格 JSON Schema。

只读工具应：

- 不保存文件、不覆盖文件、不修改几何。
- 对同一个 Creo 状态返回稳定结果。
- 同时报告原生单位和标准化后的测量结果。

改变会话状态的工具应：

- 在请求中要求固定的确认字符串。
- 明确报告模型是否被打开、创建、导入或激活。
- 不把“打开”或“创建”解释成“允许保存”。

修改几何的工具应：

- 显式指定目标模型和引用。
- 在第一次修改前完成所有输入检查。
- 执行后重生成模型。
- 测量或读取结果，并把观察到的状态返回给调用方。
- 在失败时尽量保持原模型不被部分修改。

写文件的工具应：

- 尽量与几何创建工具分开。
- 要求绝对输出路径，或明确返回实际工作目录。
- 默认拒绝目标名称的所有 Creo 版本文件。

## 模型操作生命周期

推荐的完整流程是：

```text
检查输入文件
  -> 打开或导入未保存模型
  -> 测量并确认几何
  -> 生成操作计划
  -> 创建或修改原生特征
  -> 重生成并验证
  -> 单独请求保存或导出
```

打开、导入、编辑、保存和导出是五种不同权限。这样可以检查中间结果，也能
避免一次建模请求隐式修改磁盘文件。

## CAD 输入规则

通用导入器使用本机 Creo 13.4 类型库中的 `EpfcNewModelImportType`，不猜测
枚举值。

`.prt` 有歧义：它既可能是 Creo 原生零件，也可能是 NX 零件。因此：

- Creo `.prt` 和 `.asm` 使用 `creo_open_native_model`。
- NX `.prt` 使用 `creo_import_cad`，并显式指定 `source_format: "nx"`。

STL 等网格格式可以作为参考几何，但不能默认视为可编辑的 B-rep 实体。MCP
需要报告输入的几何表达类型，Skill 再决定能否进入后续工程流程。

## 通用 MCP 建设顺序

### Creo VB API 的特征创建边界

本机 Creo 13.4 VB API 虽然公开了 `IpfcSolid.CreateFeature`，但没有提供普通
拉伸、旋转等特征的公开创建指令工厂。官方支持且能够程序化提供引用和变量
尺寸的通用途径是 `IpfcSolid.CreateUDFGroup`。

因此，核心特征能力采用“参数化 UDF + 结构化清单”的方式实现：

- UDF 保存草图和原生 Creo 特征定义。
- 清单记录 UDF 文件哈希、适用模型类型、必需引用、变量尺寸和单位规则。
- MCP 在修改模型前校验文件哈希、引用完整性、尺寸范围和输入集合。
- MCP 使用官方 UDF API 放置特征组、重生成并检查结果。
- Skill 选择 UDF 并计算工程参数，但不绕过清单验证。

当前 MCP 已实现这条基础链路：

- `creo_validate_udf_manifest` 离线解析严格 JSON 清单并校验 `.gph` 的 SHA-256。
- `creo_get_model_structure` 返回特征、表面、边、轴、点和坐标系的稳定 ID。
- `creo_get_geometry_details` 对指定表面和边 ID 返回类型、面积或长度、毫米坐标、
  相邻表面与所属特征，使无名称的导入拓扑也能被后续操作可靠引用。
- `creo_find_surfaces` 完整扫描模型表面，并按类型、面积、固定坐标位置过滤和排序，
  只返回有限候选，避免 Agent 逐个猜测匿名拓扑 ID。
- `creo_run_udf_qualification` 只接受 `verified_non_interactive=false` 的候选清单，
  在显式确认下执行一次受监督、未保存的真实放置；成功不会自动授予资格。
- `creo_place_qualified_udf` 重新校验清单、哈希、`validation_id`、Creo 精确版本、
  目标模型类型、完整引用集合和全部变量尺寸范围，并拒绝尚未取得资格的清单。
- 放置时关闭交互修复入口，调用官方 `CreateUDFGroup`，重生成并返回组成员与
  实际几何；模型保持未保存。
- `creo_update_model_metadata` 使用稳定 ID 重命名模型项目，修改命名尺寸并维护
  强类型模型参数；全部目标先解析和检查，修改后重生成，默认不保存。
- `creo_update_feature_suppression` 按特征名（不区分大小写）或稳定 ID 抑制与恢复
  模型树特征；全部目标先解析和检查，已处于目标状态的特征不发起 COM 调用，重生成
  后逐个读回状态，与请求不一致就报错。由族表、简化表示或程序压制的特征一律拒绝。
  模型保持未保存。
- `creo_get_handoff_report` 汇总特征状态、匿名特征、命名尺寸、`MCP_` 自动化归属
  参数、单位和外包络，供人工接手前检查。
- `creo_save_model_as` 与 `creo_export_model` 将原生副本和中性格式输出拆成独立、
  显式确认且禁止覆盖的操作。
- 每个 CLI 隔离操作分配 `operation_id` 并记录最小化 JSONL 审计信息；日志不包含
  请求 payload 或模型内容，可由 `creo_get_operation_log` 读取。

清单字段、单位规则和真实 Creo 资格验证步骤见
[`UDF_MANIFEST.zh-CN.md`](UDF_MANIFEST.zh-CN.md)。

不能直接把任意 `.gph` 文件交给 MCP 自动放置。缺少引用或尺寸时，Creo 会弹出
交互提示，从而破坏自动化并可能导致超时。只有通过真实 Creo 验证、带完整
清单且哈希匹配的 UDF 才能进入非交互式工具链。

在 MCP 对外接口中仍然可以提供 `create_extrude`、`create_revolve` 等高层通用
工具，但其内部可以由经过验证的 UDF 实现，而不是向调用方泄漏 Creo 的底层
放置细节。

1. 模型与引用发现
   - 列出模型、特征、基准面、轴、点、坐标系、尺寸和参数。
2. 草图能力
   - 创建草绘平面和方向引用。
   - 创建直线、圆弧、圆、中心线和构造几何。
   - 添加尺寸约束和几何约束。
3. 核心实体特征
   - 拉伸、旋转、孔、壳体、圆角、倒角、阵列、镜像和扫描。
   - 由下文的模板分派表和资格化 UDF 兑现，不是从零创建特征。
4. 特征与参数编辑
   - 已实现模型项目语义重命名、命名尺寸修改、强类型模型参数创建与更新，以及
     模型树特征的抑制与恢复（`creo_update_feature_suppression`，待真实会话验证）。
   - 排序、重生成并验证结果。
5. 装配能力
   - 创建装配、添加组件、设置装配约束。
6. 保存与交换
   - 已实现受保护的原生另存副本，以及 STEP、IGES、Parasolid 导出。

产品 Skill 只能组合这些通用能力。例如针管 Skill 可以组合旋转、拉伸和阵列；
吸塑盒 Skill 可以组合产品测量、间隙计算、拔模、壳体和圆角。

### Phase 1.5：模板分派表

Phase 1.5 的目标是在不引入 Pro/Toolkit C++ add-in 的前提下扩大特征覆盖面。
它对应竞品 MCP 里的“UI 命令直通表”，区别是每一行都要过清单校验。

一张模板分派表把一个通用动作名映射到一个可验证的资产：

| 字段 | 含义 |
|---|---|
| 动作名 | 通用动词，例如 `cavity_cut`、`seal_flange`、`draft_all` |
| 资产 | 资格化 UDF `.gph`，或带命名驱动尺寸的零件模板 |
| 引用绑定 | 每个引用绑到一个稳定角色（腔体原点坐标系、封边平面等） |
| 驱动尺寸 | 命名尺寸集合、单位、合法范围与默认值 |
| 抑制位 | 预置但默认抑制的特征（拔模、圆角），由 `creo_update_feature_suppression` 启用 |
| 交付判据 | 使该行合格的一条真实 Creo 验证记录 |

边界由 API 实际能力决定：Creo 13.4 的 VB API 不能新建原生特征，但**能修改已
存在特征的命名尺寸并重生成**，UDF 组又能携带原生特征。所以“薄”的特征工具由
`creo_place_qualified_udf`（放置特征组）、`creo_update_model_metadata`（写命名
尺寸与强类型参数）和 `creo_update_feature_suppression`（启用模板里预置的抑制
特征）组合完成，即可覆盖拉伸、切除、拔模、圆角等常见动作。Pro/Toolkit add-in
只在“凭空创建新的特征类型”或“回放 UI 命令”时才成为前提，它是这项能力的补集，
不是 Phase 1.5 的前置条件。

按本文“判断一项能力属于 MCP 还是 Skill”的判据，表的内容与表的执行分开落位：

- 表的内容（某个产品用哪些模板、尺寸怎么算）属于 Skill 或配置资源。
- 表的执行（清单校验、引用绑定、放置、写尺寸、抑制与恢复、重生成、测量）
  属于 MCP。

安全关键动作不进薄表。保存、另存副本、导出、替换既有模型必须保持为独立的、
显式确认的工具；薄表扩大的是“能改什么几何”，不是“能写什么磁盘”。

一行进入表之前，必须满足仓库 `docs/TOOL_CONVENTIONS.zh-CN.md` 的新增工具
checklist，其中写操作要求在
[`LIVE_VALIDATION.zh-CN.md`](LIVE_VALIDATION.zh-CN.md) 有真实会话通过记录。没有
记录的行只能作为候选，不得供 Skill 选择。

## 如何创建产品 Skill

当通用 MCP 能力满足需求后，再使用 `skill-creator` 创建正式 Skill。建议结构：

```text
skill-name/
├─ SKILL.md
├─ references/
│  ├─ 参数和尺寸规范
│  ├─ 工艺规则
│  └─ 检查与验收标准
├─ scripts/
│  └─ 必须确定性计算的辅助逻辑
└─ assets/
   └─ Creo 模板、参数映射或可复用资源
```

`SKILL.md` 主要描述决策、调用顺序、检查点和恢复策略；复杂计算放在脚本中，
标准、规则和较长参考资料放在 `references/`，模板放在 `assets/`。

可以分别创建：

- 通用 Creo 工程规范 Skill。
- 针管参数化建模 Skill。
- 吸塑盒设计与验证 Skill。
- 某个客户或项目的交付 Skill。

这些 Skill 可以独立升级，而不需要修改通用 Creo MCP。

## 当前过渡工具

`creo_plan_packaging_box` 和 `creo_create_packaging_box` 是早期验证连接、模板和
受保护写入链路的工具，不是目标核心接口。通用特征能力能够覆盖它们以后，
包装盒流程应迁移到 Skill，随后移除这两个专用工具。

`creo_import_step` 也是过渡接口。`creo_import_cad` 才是通用导入契约。当前不以
兼容旧接口为主要目标，因此后续接口设计不需要受这些窄工具限制。

## 测试与发布要求

MCP 使用四层验证：

1. 单元测试：验证 Schema、路径、格式识别、单位换算、计划和防覆盖逻辑。
2. 工具面契约测试：验证命名、标题、描述长度预算、注解与动词一致、写操作必须带
   确认令牌、描述里引用的工具确实存在、`tools/list` 载荷不超过预算
   （`tests/test_tool_conventions.py`，由 `creo_mcp/catalog.py` 提供检查）。
3. MCP 协议测试：验证 stdio 工具发现、注解、输入和输出 Schema。
4. 真实 Creo 测试：在与 Creo 相同的 Windows 交互会话中验证官方 COM 调用。

无需 MCP 客户端也能自检：`creo-mcp --list`、`creo-mcp --list-json`、
`creo-mcp --doctor`（加 `--probe` 会做真实连接检查）。预检结果同时是可读资源
`creo://server/status`。

新增写操作只有通过真实 Creo 测试后，才能视为可用于工程流程。Mock 可以验证
参数构造和安全约束，但不能证明 Creo 特征语义和重生成行为正确。

写操作异常后的具体停机、检查、重开原件和残留文件处理流程见
[`ENGINEERING_STANDARD.zh-CN.md`](ENGINEERING_STANDARD.zh-CN.md) 的“异常恢复”。

## 判断一项能力属于 MCP 还是 Skill

判断标准是：一个完全不同的产品，能否在不继承针管或包装术语的情况下自然
复用该能力。

- 能复用，并且是确定性的 Creo 操作：放 MCP。
- 负责选择、排序或约束操作以满足产品和工艺要求：放 Skill。
- 是公司、客户或项目的标准值与模板：放配置或资源文件。

这个边界保证 MCP 保持通用，Skill 保持灵活，工程流程保持可维护。
